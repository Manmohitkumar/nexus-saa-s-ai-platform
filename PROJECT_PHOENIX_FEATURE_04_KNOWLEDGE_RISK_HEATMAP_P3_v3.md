# PROJECT PHOENIX - FEATURE 04

## Knowledge Risk Heatmap

### Project Phoenix Prompt Protocol (P3) v3.0

## Dependency Chain

Feature 1 Organizational Digital Brain
-> Feature 2 Decision Time Machine
-> Feature 3 Employee Exit Simulation
-> Feature 4 Knowledge Risk Heatmap

Feature capability inheritance:

- Organizational Brain provides organizational knowledge
- Decision Time Machine provides historical decision intelligence
- Exit Simulation provides knowledge dependency and resilience scores
- Knowledge Risk Heatmap visualizes and analyzes all upstream intelligence

No duplicate logic is permitted.

## Foundation Dependency Rule

Assume Features 1, 2, and 3 are fully implemented and are the only architecture foundation for Feature 4.

Feature 4 must extend existing modules only and must not create parallel implementations of:

- Knowledge graph
- Memory architecture
- AI framework
- Authentication
- Independent ingestion pipeline
- Duplicate decision or workforce engines

## Master Prompt

```text
Assume that Feature #1 (Organizational Digital Brain), Feature #2 (Decision Time Machine), and Feature #3 (Employee Exit Simulation) have already been fully implemented and serve as the core architecture of Project Phoenix. Reuse every existing module including the Organizational Knowledge Graph, shared memory architecture, AI agents, APIs, event bus, authentication, reusable UI components, database schemas, Workforce Intelligence Services, Decision Intelligence Engine, Organizational Resilience Services, and coding standards. Never recreate any existing functionality. Extend only the capabilities required for Knowledge Risk Heatmap while maintaining complete compatibility with the Project Phoenix ecosystem.

You are an elite engineering organization consisting of Principal Software Architects, Enterprise AI Researchers, Knowledge Management Specialists, Organizational Intelligence Experts, Data Visualization Engineers, UX Designers, Senior Full-Stack Engineers, Security Architects, DevOps Engineers, Product Managers, and Business Intelligence Architects.

Your mission is to design and implement the Knowledge Risk Heatmap, an enterprise intelligence capability that continuously measures, predicts, and visualizes organizational knowledge risks in real time. This feature is not a dashboard, reporting module, or chart generator. Instead, it should function as the organization's visual intelligence layer that transforms complex organizational risk into an immediately understandable and actionable experience.

The Knowledge Risk Heatmap must never collect enterprise data independently. It must consume organizational intelligence already produced by the Organizational Digital Brain, historical context from the Decision Time Machine, and dependency analysis from the Employee Exit Simulation. Every visualization should be generated by reasoning over existing knowledge rather than creating duplicate analytical pipelines.

Extend the existing Organizational Knowledge Graph by introducing reusable Risk Intelligence metadata. Every graph node including employees, teams, repositories, services, APIs, databases, infrastructure, documentation, architectural decisions, business capabilities, projects, and workflows should continuously maintain risk-related attributes such as Documentation Coverage Score, Knowledge Concentration Score, Ownership Distribution Score, Organizational Resilience Score, Technical Debt Score, Decision Complexity Score, Collaboration Diversity Score, Bus Factor, Update Frequency, Critical Dependency Score, Operational Exposure Score, AI Confidence Score, and Historical Stability Score. These attributes must evolve automatically as the Organizational Digital Brain learns new information.

Implement a reusable Risk Intelligence Engine that continuously evaluates organizational health using graph traversal, historical decision analysis, documentation quality, repository ownership, contribution history, collaboration networks, deployment history, incident frequency, architectural complexity, onboarding readiness, succession planning, and organizational dependency analysis. This engine should generate predictive insights rather than static reports and expose reusable services that future features can consume.

Extend the existing multi-agent framework by introducing a Risk Intelligence Agent responsible only for aggregating organizational risks and coordinating risk evaluation. This agent must collaborate with the Planner Agent, Memory Agent, Decision Intelligence Agent, Workforce Intelligence Agent, Recommendation Agent, Explainability Agent, and Organizational Brain. It should never duplicate search, reasoning, graph traversal, or memory responsibilities already implemented in previous features. All communication must continue through LangGraph orchestration and the existing Model Context Protocol (MCP) architecture.

Develop a Dynamic Heatmap Visualization Engine integrated directly into the Organizational Brain. Every node within the graph should dynamically change color according to calculated organizational risk. Green should represent healthy organizational knowledge, yellow should indicate moderate concern, orange should represent increasing organizational vulnerability, and red should highlight critical knowledge loss, undocumented systems, ownership concentration, or high operational exposure. Risk propagation should animate naturally across connected services so users can immediately understand downstream organizational impact.

Support multiple visualization modes including Organization Heatmap, Team Heatmap, Repository Heatmap, Service Heatmap, API Heatmap, Documentation Heatmap, Decision Heatmap, Infrastructure Heatmap, Business Capability Heatmap, Knowledge Ownership Heatmap, Collaboration Heatmap, and Organizational Resilience Heatmap. Users should be able to filter by department, project, technology stack, business unit, repository, employee, customer, environment, or time period while preserving the same interactive Organizational Brain experience introduced in Feature #1.

Implement intelligent predictive analytics capable of identifying future organizational risks before they occur. Detect undocumented critical systems, single points of organizational failure, isolated domain experts, aging architectural decisions, declining documentation quality, increasing technical debt, inactive repositories, unstable ownership transitions, declining collaboration, and emerging operational bottlenecks. Predictions must always include evidence, reasoning traces, confidence scores, historical comparisons, contributing factors, and recommended mitigation strategies.

Develop reusable frontend components including Risk Heatmap Layer, Organizational Health Dashboard, Risk Timeline Viewer, Documentation Coverage Explorer, Knowledge Concentration Map, Dependency Risk Explorer, Organizational Exposure Matrix, Technical Debt Visualizer, Ownership Distribution Viewer, AI Recommendation Panel, and Historical Risk Comparison Charts. These components must extend the existing Project Phoenix design system instead of introducing independent UI frameworks.

Integrate the heatmap seamlessly into the Organizational Brain. Users should never leave the graph interface. Activating Heatmap Mode should transform the existing Digital Brain into a live organizational risk visualization while preserving graph navigation, zooming, searching, filtering, timeline replay, and contextual exploration. Selecting any high-risk node should immediately display ownership information, historical decisions, related documentation, employee dependencies, architectural evolution, affected systems, AI reasoning, mitigation recommendations, and projected organizational impact.

Implement a reusable Recommendation Intelligence Service capable of generating prioritized action plans. Recommendations should include documentation improvements, ownership redistribution, mentoring assignments, knowledge transfer sessions, architecture reviews, succession planning, dependency reduction strategies, technical debt reduction, and organizational restructuring proposals. These recommendations must reuse existing AI reasoning services rather than implementing a separate recommendation engine.

Extend the backend by introducing reusable Risk Services, Predictive Analytics Services, Organizational Health Services, Visualization APIs, Historical Comparison Services, and Recommendation APIs. These services must integrate with the existing architecture and expose reusable interfaces for future consumption by AI Mentor, Autonomous Documentation Engine, Organizational Intelligence Engine, and Executive Intelligence Dashboard.

Every AI-generated organizational risk assessment must include affected systems, ownership analysis, supporting evidence, historical trends, related architectural decisions, dependency chains, confidence score, business impact assessment, estimated organizational exposure, and actionable recommendations. Never produce unsupported conclusions or isolated risk scores.

The Knowledge Risk Heatmap must continuously evolve. Whenever new documentation, code commits, architectural decisions, deployments, ownership changes, incidents, or organizational events occur, the Organizational Brain should automatically recalculate organizational risk, update visualization layers, propagate changes across connected entities, and preserve historical snapshots for trend analysis.

Engineer this feature as a production-grade enterprise intelligence capability capable of analyzing millions of organizational relationships, thousands of repositories, hundreds of teams, and years of historical organizational knowledge while maintaining high performance, cloud-native scalability, low-latency visualization, explainability, fault tolerance, observability, and enterprise security.

The final implementation should not resemble a monitoring dashboard or analytics report. It should feel like a living organizational health system where executives, architects, engineering managers, and developers can instantly understand where knowledge is healthy, where risks are emerging, why those risks exist, and what actions should be taken before organizational failures occur. This feature should become the visual intelligence layer of Project Phoenix while naturally extending every capability implemented in Features #1, #2, and #3 without introducing architectural conflicts or duplicate systems.
```
